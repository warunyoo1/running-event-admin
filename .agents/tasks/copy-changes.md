# รายการแก้ข้อความหน้า Admin (ภาษาไทย)

แก้เฉพาะข้อความที่ผู้ใช้เห็นใน `src/` ไม่แตะ logic, props, route, การเรียก API, ชื่อ CSS class และค่า enum ที่ส่งให้ API (เช่น `super_admin`, `archived`, `slip_uploaded` ยังเหมือนเดิม)

## 1. ศัพท์กลาง (Glossary)

| ใช้คำนี้ | แทนคำเดิม | หมายเหตุ |
|---|---|---|
| สร้างผู้ใช้ | เชิญผู้ใช้ | ระบบสร้างบัญชีพร้อมรหัสผ่านชั่วคราว ไม่ส่งอีเมลเชิญ |
| ซ่อนงาน / แสดงงานอีกครั้ง | เก็บถาวร / กู้คืน | งานที่ซ่อนจะไม่แสดงบนเว็บรับสมัครและรับสมัครใหม่ไม่ได้ ข้อมูลยังอยู่ครบ แสดงกลับได้ |
| ลบงาน (ถาวร) | ลบงานถาวร | ลบได้เฉพาะงานที่ยังไม่มีออเดอร์ กู้คืนไม่ได้ |
| ปิดใช้งาน / เปิดใช้งาน (ผู้ใช้) | เหมือนเดิม | เข้าสู่ระบบไม่ได้ ข้อมูลอยู่ครบ เปิดกลับได้ |
| ลบผู้ใช้ | ลบถาวร | ทำได้เฉพาะผู้ใช้ที่ปิดใช้งานแล้วและไม่เคยมีประวัติ |
| ลิงก์ของงาน (ส่วนท้ายของ URL) | ลิงก์งานวิ่ง (slug) | |
| จำนวนที่รับ | โควตา | |
| จองแล้ว | ที่นั่งที่จอง | นับรวมคนที่ยังไม่จ่ายเงิน ไม่นับที่ยกเลิก/หมดเวลา |
| ที่ว่าง | คงเหลือ | |
| ระยะวิ่ง | ระยะ | |
| เลข BIB (เลขหน้าอก) | เลข BIB | ใส่คำอธิบายที่หัวตาราง/คำอธิบายหน้า ที่อื่นใช้ "เลข BIB" |
| เลขพัสดุ / บริษัทขนส่ง | ผู้ให้บริการขนส่ง | |
| ชุดวิ่ง | อุปกรณ์ | เสื้อ + เลข BIB |
| รับเองที่หน้างาน / ส่งพัสดุ | รับด้วยตนเอง / จัดส่งทางพัสดุ | |
| ประวัติการใช้งาน | เหมือนเดิม | |
| บันทึกของทีมงาน | บันทึกภายใน | ผู้สมัครไม่เห็น |
| ดาวน์โหลด … (CSV) | ส่งออก … | ชื่อปุ่มบอกว่าได้ไฟล์อะไร |
| จัดการระบบ · ทุกงาน | ส่วนกลาง | |
| สิทธิ์ใช้งาน | บทบาท | |
| อนุมัติสลิป / ปฏิเสธสลิป | อนุมัติการชำระเงิน / สลิปไม่ผ่าน | ปุ่มเป็นคำกริยา |

ชื่อสิทธิ์ใช้งาน (ค่าที่ส่ง API ไม่เปลี่ยน) และคำอธิบายหนึ่งบรรทัด (ตรวจกับ route guard ของ API แล้ว):

| ค่า | ชื่อที่แสดง | คำอธิบาย |
|---|---|---|
| super_admin | ผู้ดูแลระบบ | ทำได้ทุกอย่าง รวมถึงสร้างและแก้ไขงานวิ่ง และจัดการผู้ใช้ |
| reviewer | เจ้าหน้าที่ (เดิม เจ้าหน้าที่ตรวจสลิป) | ตรวจสลิป ยกเลิกออเดอร์ แก้ที่อยู่ ใส่เลขพัสดุ และกรอกเลข BIB ได้ แต่แก้ไขงานวิ่งและจัดการผู้ใช้ไม่ได้ |
| viewer | ดูได้อย่างเดียว (เดิม ผู้ดูข้อมูล) | ดูข้อมูลและดาวน์โหลดไฟล์ได้อย่างเดียว แก้ไขอะไรไม่ได้ |

คำอธิบายนี้อยู่ที่ `roleDescriptions` ใน `format.ts` และแสดง 3 ที่: กล่องอธิบายใต้ตารางผู้ใช้, ใต้ช่องเลือกสิทธิ์ในฟอร์มผู้ใช้, และหน้าต่าง "วิธีใช้งาน"

สถานะออเดอร์ (ตรงกับ state machine ใน `order-state.ts`: pending -> slip_uploaded -> paid; rejected ส่งสลิปใหม่ได้; cancelled/expired/paid เป็นสถานะสุดท้าย):

| ค่า | เดิม | ใหม่ |
|---|---|---|
| pending | รอชำระเงิน | รอชำระเงิน (เหมือนเดิม) |
| slip_uploaded | รอตรวจสลิป | รอตรวจสลิป (เหมือนเดิม) |
| paid | ชำระเงินแล้ว | ชำระเงินแล้ว (เหมือนเดิม) |
| rejected | สลิปไม่ผ่าน | สลิปไม่ผ่าน (เหมือนเดิม) |
| expired | หมดอายุ | หมดเวลาชำระเงิน (ออเดอร์ที่รอชำระเงินนานเกินกำหนด ค่าเริ่มต้นของ API คือ 24 ชม.) |
| cancelled | ยกเลิกแล้ว | ยกเลิกแล้ว (เหมือนเดิม) |

สถานะงานวิ่ง: draft แบบร่าง -> ฉบับร่าง, open/closed/upcoming เหมือนเดิม และเพิ่มคำอธิบายใต้ช่องเลือกสถานะ (draft ยังไม่แสดงบนเว็บ / open รับสมัครได้ / closed ปิดรับสมัคร / upcoming แสดงแต่ยังรับสมัครไม่ได้) ตรวจกับ `loadOpenEvent` ของ API แล้ว

## 2. รายการเปลี่ยนข้อความ (เก่า -> ใหม่)

### ผู้ใช้ (`users/page.tsx`)
- ปุ่ม/หัวข้อ dialog: เชิญผู้ใช้ใหม่ -> สร้างผู้ใช้ใหม่
- ปุ่มบันทึก: บันทึกผู้ใช้ -> สร้างผู้ใช้ (ตอนสร้าง) / บันทึก (ตอนแก้ไข); กำลังบันทึก… -> กำลังสร้าง… (ตอนสร้าง)
- Toast: บันทึกผู้ใช้แล้ว -> สร้างผู้ใช้แล้ว ระบบไม่ส่งอีเมล กรุณาแจ้งรหัสผ่านชั่วคราวให้เขาเอง (ตอนสร้าง) / บันทึกข้อมูลผู้ใช้แล้ว (ตอนแก้ไข)
- คำอธิบายหน้า: กำหนดบทบาทของทีมที่เข้ามาจัดการงานวิ่ง ระบบไม่ส่งอีเมลเชิญ… -> สร้างบัญชีและกำหนดสิทธิ์ให้ทีมงาน ระบบจะไม่ส่งอีเมลให้ผู้ใช้ กรุณาแจ้งอีเมลและรหัสผ่านชั่วคราวให้เขาเอง
- คำใบ้ในฟอร์ม: ผู้ใช้จะถูกแจ้งให้เปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก -> (สร้าง) ระบบไม่ส่งอีเมลให้ กรุณาแจ้งรหัสผ่านนี้ให้เขาเอง เขาจะต้องเปลี่ยนรหัสผ่านตอนเข้าสู่ระบบครั้งแรก / (แก้ไข) ถ้าตั้งรหัสผ่านใหม่ เขาต้องเปลี่ยนรหัสผ่านอีกครั้งตอนเข้าสู่ระบบ (ตรงกับ API: เปลี่ยนรหัสให้คนอื่นแล้วตั้ง mustChangePassword)
- ปุ่มสร้างรหัสผ่านชั่วคราว -> สุ่มรหัสผ่านให้; คัดลอก -> คัดลอกรหัสผ่าน
- รหัสผ่านใหม่ (เว้นว่างหากไม่เปลี่ยน, อย่างน้อย 10 ตัวอักษร) -> รหัสผ่านใหม่ (เว้นว่างไว้ถ้าไม่เปลี่ยน, อย่างน้อย 10 ตัว); รหัสผ่านชั่วคราว (… ตัวอักษร) -> (… ตัว)
- หัวคอลัมน์/ช่อง: บทบาท -> สิทธิ์ใช้งาน (เพิ่มคำอธิบายใต้ช่องเลือก)
- สถานะในตาราง: เปิดใช้งาน/ปิดใช้งาน -> ใช้งานอยู่/ปิดใช้งานแล้ว (ปุ่มยังเป็นคำกริยา เปิดใช้งาน/ปิดใช้งาน)
- ต้องเปลี่ยนรหัสผ่าน -> ยังใช้รหัสผ่านชั่วคราว
- ปุ่มลบ: ลบถาวร -> ลบผู้ใช้ (ปุ่มยืนยัน: ลบถาวร -> ลบผู้ใช้ถาวร)
- Dialog ปิดใช้งาน: …จะเข้าสู่ระบบไม่ได้จนกว่าจะเปิดใช้งานอีกครั้ง -> เขาจะเข้าสู่ระบบไม่ได้ แต่ข้อมูลและประวัติยังอยู่ กดเปิดใช้งานเมื่อไรก็กลับมาใช้ได้
- Dialog เปิดใช้งาน: เพิ่ม "เขาจะเข้าสู่ระบบได้ตามปกติ"
- Dialog ลบ: …ถ้าผู้ใช้เคยมีประวัติการใช้งานจะลบไม่ได้ ให้ปิดใช้งานไว้แทน -> ลบแล้วกู้คืนไม่ได้ ถ้าเขาเคยใช้งานระบบมาก่อนจะลบไม่ได้ ให้ปิดใช้งานแทน
- ไม่สามารถปิดใช้งานบัญชีของตัวเองได้ -> ปิดใช้งานบัญชีของตัวเองไม่ได้; ไม่สามารถเปลี่ยนบทบาทหรือสถานะ… -> เปลี่ยนสิทธิ์ใช้งานหรือสถานะของบัญชีตัวเองไม่ได้
- N ผู้ใช้ -> N คน; กำลังดำเนินการ… -> กำลังทำรายการ…
- เฉพาะผู้ดูแลระบบเท่านั้นที่จัดการผู้ใช้ได้ -> หน้านี้ใช้ได้เฉพาะผู้ดูแลระบบ
- คัดลอกไม่สำเร็จ กรุณาคัดลอกจากช่องรหัสผ่าน -> คัดลอกไม่สำเร็จ ให้เลือกรหัสผ่านในช่องแล้วคัดลอกเอง
- กล่องอธิบายสิทธิ์: ใช้ `roleDescriptions` (เดิม: จัดการทุกโมดูล / ดูออเดอร์ ตรวจสลิป และยืนยันการชำระเงิน / ดูข้อมูลและส่งออกรายงาน โดยไม่แก้ไขข้อมูล) คำอธิบาย reviewer เดิมไม่ครบ ไม่บอกว่ายกเลิกออเดอร์ ใส่เลขพัสดุ แก้ที่อยู่ กรอก BIB ได้

### งานวิ่ง (`events/page.tsx`)
- ปุ่มการ์ด: เก็บถาวร -> ซ่อนงาน; กู้คืน -> แสดงงานอีกครั้ง; ลบ -> ลบงาน; จัดการงาน -> แก้ไขงาน
- ป้าย: เก็บถาวร -> ซ่อนอยู่; ตัวกรอง ใช้งานอยู่/เก็บถาวร -> งานที่แสดงอยู่/งานที่ซ่อนไว้; (sr-only) การแสดงผล -> งานที่แสดง
- Dialog ซ่อน: เก็บถาวรงานวิ่ง -> ซ่อนงานวิ่ง; ข้อความ -> ซ่อนงาน «…»? งานจะไม่แสดงบนเว็บรับสมัครและรับสมัครใหม่ไม่ได้ แต่ข้อมูลออเดอร์และรูปภาพยังอยู่ครบ กด “แสดงงานอีกครั้ง” เมื่อไรก็ได้; ปุ่ม เก็บถาวร -> ซ่อนงาน
- Dialog ลบ: ปุ่ม ลบถาวร -> ลบงานถาวร; ข้อความ -> ลบงาน «…» ถาวร? ระยะวิ่งและรูปภาพทั้งหมดจะหายไปและกู้คืนไม่ได้ ลบได้เฉพาะงานที่ยังไม่มีออเดอร์ ถ้าไม่แน่ใจให้เลือก “ซ่อนงาน” แทน
- เมื่อลบไม่ได้เพราะมีออเดอร์: งานนี้มีออเดอร์แล้ว ลบถาวรไม่ได้ -> งานนี้มีออเดอร์แล้ว จึงลบไม่ได้ ให้ซ่อนงานแทน ข้อมูลออเดอร์จะยังอยู่ครบ (ถ้าซ่อนอยู่แล้ว ตัดประโยคหลังออก); ปุ่ม เก็บถาวรแทน -> ซ่อนงานแทน
- Toast: กู้คืนงาน «…» แล้ว -> แสดงงาน «…» อีกครั้งแล้ว; เก็บถาวรงาน «…» แล้ว -> ซ่อนงาน «…» แล้ว; บันทึกงานวิ่งแล้ว -> บันทึกการแก้ไขแล้ว; สร้างงานวิ่งแล้ว เพิ่มรูปภาพได้เลย -> …เพิ่มรูปภาพต่อได้เลย; สร้างงานวิ่งและอัปโหลดรูป N รูปแล้ว -> สร้างงานวิ่งและเพิ่มรูป N รูปแล้ว; …แต่อัปโหลดรูปไม่สำเร็จ -> …แต่เพิ่มรูปไม่สำเร็จ
- ปุ่ม/หัวข้อ: สร้างงานวิ่ง -> สร้างงานวิ่งใหม่; ตั้งค่างานวิ่ง -> แก้ไขงานวิ่ง; ปุ่มบันทึกงานวิ่ง -> สร้างงานวิ่ง (ตอนสร้าง) / บันทึก (ตอนแก้ไข)
- คำอธิบายหน้า: ดูงานวิ่งทั้งหมด สร้างงาน และตั้งค่าการรับสมัครในที่เดียว -> สร้างงานวิ่ง แก้ไขรายละเอียด ระยะวิ่ง ราคา และรูปภาพ
- ที่นั่งที่จอง -> จองแล้ว (ข้อความและ aria-label: จองแล้ว N จากจำนวนที่รับ M คน); เริ่มต้น ฿ -> ราคาเริ่มต้น ฿
- ฟอร์ม: ลิงก์งานวิ่ง (slug) -> ลิงก์ของงาน (ส่วนท้ายของ URL); คำใบ้ -> ใช้ได้เฉพาะตัวอักษรอังกฤษพิมพ์เล็ก ตัวเลข และขีดกลาง (-) · ระวัง: ถ้าเปลี่ยนลิงก์ ลิงก์เดิมที่แชร์ไปแล้วจะเปิดไม่ได้ / ระบบสร้างให้จากชื่องาน แก้เองได้ / ชื่องานเป็นภาษาไทย กรุณาพิมพ์ลิงก์เป็นภาษาอังกฤษเอง; ปุ่ม ลองใช้ X -> ใช้ X แทน
- คำโปรย -> คำโปรย (ข้อความสั้นๆ ใต้ชื่องาน); ปิดรับสมัคร (ช่องวันที่) -> วันปิดรับสมัคร; สถานะ -> สถานะงาน (+คำอธิบายใต้ช่อง); ประเภท -> ประเภทงาน
- ระยะและราคา -> ระยะวิ่งและราคา; ระยะ -> ชื่อระยะวิ่ง; โควตา (คน) -> จำนวนที่รับ (คน); ลบระยะ -> ลบระยะวิ่งนี้; เพิ่มระยะ -> เพิ่มระยะวิ่ง
- งานนี้มีออเดอร์แล้ว การแก้ไขชื่อ ราคา หรือโควตาของระยะอาจถูกปฏิเสธ -> …การแก้ชื่อ ราคา หรือจำนวนที่รับของระยะวิ่งอาจทำไม่ได้
- ประเภทงาน: ถนน -> วิ่งถนน; เทรล -> วิ่งเทรล; ฟันรัน -> ฟันรัน (วิ่งสนุก)

### รูปภาพของงาน (`event-images.tsx`, `event-images-panel.tsx`)
- ปุ่มลบรูป: ลบ -> ลบรูป (aria-label: ลบรูป <ชื่อรูป>); ยืนยัน: ลบรูปนี้ใช่หรือไม่ -> ลบรูปนี้? กู้คืนไม่ได้

- ลองใหม่ -> ลองอีกครั้ง (ปุ่มในหน้า error)
- ข้อความ error ของ admin เอง: เกิดข้อผิดพลาด กรุณาลองใหม่อีกครั้ง -> เกิดข้อผิดพลาด กรุณาลองอีกครั้ง ถ้ายังไม่หายให้แจ้งผู้ดูแลระบบ; เชื่อมต่อเซิร์ฟเวอร์ไม่ได้ -> เชื่อมต่อระบบไม่ได้ ตรวจอินเทอร์เน็ตแล้วลองอีกครั้ง; ข้อมูลจากเซิร์ฟเวอร์ไม่ถูกต้อง -> ระบบตอบกลับผิดปกติ กรุณาลองอีกครั้ง ถ้ายังไม่หายให้แจ้งผู้ดูแลระบบ; ลิงก์นี้ถูกใช้แล้ว (SLUG_TAKEN) -> ลิงก์นี้มีงานอื่นใช้อยู่แล้ว ลองเปลี่ยนชื่อลิงก์

### คงเดิม (ตั้งใจ)
ภาพรวม, ออเดอร์, ตรวจสลิป, ผู้สมัคร, รายงาน, จัดการงานวิ่ง, ผู้ใช้และสิทธิ์, ประวัติการใช้งาน (ชื่อเมนู), ชื่อสถานะ รอชำระเงิน/รอตรวจสลิป/ชำระเงินแล้ว/สลิปไม่ผ่าน/ยกเลิกแล้ว/เปิดรับสมัคร/ปิดรับสมัคร/เร็วๆ นี้, ชื่อประเภทรูป, ชื่อสี, ข้อความหน้า login ส่วน marketing, คำว่า CSV/BIB/QR/email, คำว่า "อัปโหลด" (คนใช้กันทั่วไป)

## 3. ข้อความจาก API ที่อาจสับสน (ไม่ได้แก้ API ให้ผู้ใช้ตัดสินใจ)

Admin แสดง `error.message` จาก API ตรงๆ ถ้าไม่มี field error จึงเห็นข้อความเหล่านี้ (ไฟล์ใน `running-event-api/src`)

| ข้อความปัจจุบัน | ที่มา | เสนอ |
|---|---|---|
| slug นี้ถูกใช้แล้ว | event-write.service, error-handler | ลิงก์นี้มีงานอื่นใช้อยู่แล้ว (admin override เฉพาะช่อง slug แล้ว) |
| ต้องมี super_admin ที่ใช้งานอยู่อย่างน้อย 1 คน | user.service | ต้องมีผู้ดูแลระบบที่ใช้งานอยู่อย่างน้อย 1 คน |
| ปิดใช้งานหรือเปลี่ยนบทบาทของบัญชีตัวเองไม่ได้ | user.service | ปิดใช้งานหรือเปลี่ยนสิทธิ์ใช้งานของบัญชีตัวเองไม่ได้ |
| สถานะผู้ใช้เปลี่ยนไปแล้ว กรุณาลองใหม่ | user.service | มีคนอื่นเพิ่งแก้ผู้ใช้นี้ กรุณาโหลดหน้าใหม่แล้วลองอีกครั้ง |
| งานนี้มีออเดอร์แล้ว ไม่สามารถลบถาวรได้ ให้เก็บถาวรแทน | event-write.service | งานนี้มีออเดอร์แล้ว ลบไม่ได้ ให้ซ่อนงานแทน (ให้ศัพท์ตรงกับปุ่ม) |
| มีผู้กำลังจองที่นั่งอยู่ กรุณาลองใหม่ภายหลัง หรือเก็บถาวรแทน | event-write.service | ตอนนี้มีคนกำลังสมัครอยู่ ลองใหม่ภายหลัง หรือซ่อนงานแทน |
| โควตาต้องไม่น้อยกว่าจำนวนที่จองแล้ว / โควตาต้องอย่างน้อย 1 / โควตาต้องเป็นจำนวนเต็ม | event-write.service, event.validator | เปลี่ยนคำว่าโควตาเป็น จำนวนที่รับ |
| มีออเดอร์แล้ว ไม่สามารถแก้ราคาหรือโควตาของระยะได้ (และชื่อ/ลบระยะ) | event-write.service | งานนี้มีออเดอร์แล้ว จึงแก้ราคาหรือจำนวนที่รับของระยะวิ่งไม่ได้ |
| ออเดอร์นี้ไม่สามารถยกเลิกได้ในสถานะปัจจุบัน | order-admin.service | ออเดอร์นี้ยกเลิกไม่ได้แล้ว (ชำระเงินแล้ว ถูกยกเลิก หรือหมดเวลา) |
| แก้ไขที่อยู่ได้เฉพาะออเดอร์จัดส่งที่ยังไม่ได้ใส่เลขพัสดุและยังไม่ถูกยกเลิก/หมดอายุ | order-admin.service | แก้ที่อยู่ได้เฉพาะออเดอร์ส่งพัสดุที่ยังไม่มีเลขพัสดุ และไม่ถูกยกเลิกหรือหมดเวลา |
| เลขอ้างอิงนี้ถูกใช้กับออเดอร์ที่ชำระแล้ว | review.service, error-handler | เลขอ้างอิงการโอนนี้ถูกใช้กับออเดอร์อื่นแล้ว ตรวจว่าสลิปซ้ำหรือไม่ |
| กรุณากรอกขนส่ง | admin.validator | กรุณากรอกบริษัทขนส่ง |
| alt ยาวได้ไม่เกิน N ตัวอักษร | event.validator | คำอธิบายรูปยาวได้ไม่เกิน N ตัวอักษร |
| slug ใช้ได้เฉพาะ a-z 0-9 และ - | event.validator | ลิงก์ใช้ได้เฉพาะ a-z 0-9 และ - |
| รูปแบบวันที่ต้องเป็น YYYY-MM-DD / เวลาต้องเป็น HH:mm | event.validator | วันที่ไม่ถูกต้อง กรุณาเลือกใหม่ / เวลาไม่ถูกต้อง เช่น 05:30 |
| ไม่มีข้อมูลที่จะแก้ไข | event.validator | ยังไม่ได้แก้อะไร |
| ชื่อระยะซ้ำกัน / รายการรูปภาพซ้ำกัน | event.validator | มีชื่อระยะวิ่งซ้ำกัน / เลือกรูปซ้ำกัน |

| ข้อมูลซ้ำ | error-handler | มีข้อมูลนี้อยู่แล้ว |

ข้อความที่ชัดอยู่แล้วและไม่ต้องแก้: ไม่พบออเดอร์/ผู้ใช้/รูปภาพ, อีเมลหรือรหัสผ่านไม่ถูกต้อง, รหัสผ่านต้องมีอย่างน้อย 10 ตัวอักษร, ต้องปิดใช้งานผู้ใช้ก่อนจึงจะลบถาวรได้, ผู้ใช้นี้มีประวัติการใช้งานในระบบ ให้ปิดใช้งานแทนการลบ, อนุมัติ/ปฏิเสธได้เฉพาะออเดอร์ที่รอตรวจสลิป

## 4. สิ่งที่ยังไม่ได้ตรวจ
- ไม่ได้รันหน้าเว็บจริงและไม่ได้ถ่ายภาพหน้าจอ (ต้องตั้ง API ท้องถิ่น + MongoDB ชั่วคราว + ข้อมูลตัวอย่างออเดอร์/สลิป ซึ่งหนักเกินกว่าที่คุ้ม) จึงยังไม่เห็นภาพจริงว่าข้อความที่ยาวขึ้นล้นปุ่ม/ตาราง/การ์ดหรือไม่ จุดที่ควรเปิดดู: ปุ่มบนการ์ดงานวิ่ง (แสดงงานอีกครั้ง + ลบงาน), หัวตาราง "เลข BIB (เลขหน้าอก)", คำอธิบายสิทธิ์ใต้ช่องเลือกในฟอร์มผู้ใช้, ปุ่ม "ดาวน์โหลด … (CSV)" ที่หัวหน้า
- ไม่ได้ตรวจด้วยโปรแกรมอ่านหน้าจอ aria-label ที่เปลี่ยนยังมีคำเดียวกับข้อความที่เห็น (เช่น ลบรูป <ชื่อรูป>)
- ผลของ "ซ่อนงาน" ต่อออเดอร์ที่มีอยู่แล้ว (เช่น ผู้สมัครเดิมส่งสลิปต่อได้ไหม) ไม่ได้ตรวจใน API ข้อความจึงพูดเฉพาะที่ยืนยันได้ คือไม่แสดงบนเว็บ รับสมัครใหม่ไม่ได้ ข้อมูลยังอยู่ แสดงกลับได้
